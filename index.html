Bot API Reference

Welcome to the official YukiChat Bot API documentation. The API allows you to build powerful bots using simple HTTPS requests.

Authentication

All queries to the YukiChat Bot API must be served over HTTPS and need to be presented in this form:

https://yukichat.yourworker.workers.dev/bot<token>/METHOD_NAME

You can obtain your authentication token by messaging @YukiFather inside YukiChat.

Requests must be sent as POST using application/json.

Architecture & Data Flow

YukiChat is built entirely on Cloudflare's Edge network, utilizing Workers for compute and D1 (SQLite) for ultra-fast, globally distributed database storage. Below is the scheme explaining how Bots interact with the ecosystem.

📱 YukiChat Client (Browser / PWA)
⚡ Cloudflare Worker (REST API & WebSockets)
🗄️ Cloudflare D1 (SQLite)

Stores Users, Messages,
Tokens, & Stickers

🤖 Webhook Dispatcher
Internal System Bots
(@YukiFather, @Stickers)
Developer Servers
(Python, Node.js, PHP)

How it works

1. Message Dispatching: When a user sends a message to a chat, the Cloudflare Worker inserts the message into the D1 database. Instantly, it checks if any is_bot users are members of that chat.

2. The Background Execution: If bots are present, the Worker uses ctx.waitUntil() to fire HTTP POST requests (Webhooks) to the bot developers in the background. This ensures the human user's app never lags while waiting for a bot to respond.

3. System Bots: Bots like @YukiFather (for bot creation) and @Stickers (for sticker packs) do not require an external server. Their logic is hardcoded directly inside the Cloudflare Worker, meaning they respond with zero latency.

4. Developer Bot Responses: When your Python or Node.js server receives a Webhook, it processes the text and sends an HTTP POST request back to /bot<token>/sendMessage. The Worker verifies your token, writes the response to the D1 database, and the clients sync the new message.

Frequently Asked Questions

Everything you need to know about building, managing, and interacting with YukiChat bots.

How do I create a bot?

Open YukiChat, search for @YukiFather, and send the /start command. Then, send /newbot <your_bot_name>. Note that your bot's username must end in "bot" (e.g., SupportBot, weather_bot). YukiFather will reply with your unique Bot Token.

Do I need my own server to run a bot?

Yes. YukiChat provides the API, but you need to write the code that dictates what your bot says and does. You can host your bot code on a VPS, Heroku, Vercel, or even another Cloudflare Worker. You can receive messages either via Webhooks (recommended) or by polling getUpdates.

What are System Bots?

System Bots (like @YukiFather and @Stickers) are official bots built directly into the YukiChat core infrastructure. They don't have external servers; their logic runs directly on the edge. Because of this, they do not require the "bot" suffix in their names and they have the Verified blue tick by default.

How do I create a Custom Sticker Pack?

Search for @Stickers in YukiChat. Send /newpack <shortname> <Title>. Once created, send an image to the bot with the caption /add <shortname> 👽 (replacing the alien with your desired emoji). Your sticker pack is now immediately available via the API and the YukiChat UI!

How do Inline Keyboards work?

When calling a method like sendMessage, you can pass a JSON object to the reply_markup parameter. It should contain an array of arrays representing rows of buttons. When a user clicks a button, a CallbackQuery event is dispatched to your bot's Webhook containing the callback_data you assigned to that button.

Can bots read all messages in a group?

By default, yes. If a bot is added to a group or channel, the Webhook dispatcher will send every message to the bot's server. Ensure your bot's server drops updates it doesn't need to save processing power.
